# DGLab-Majsoul

通过雀魂网页版的牌局事件，触发你设置的 DG-LAB 反馈规则。

当前版本为 **v1.0.0**，使用 Tampermonkey 脚本获取事件，通过网页控制台连接 DG-LAB 4 App。支持自定义事件、A/B 通道独立规则、强度调整和多波形播放。

- [项目首页](https://dglab-majsoul.pages.dev/)
- [开始游玩](https://dglab-majsoul.pages.dev/play/)
- [安装 / 更新脚本](https://dglab-majsoul.pages.dev/userscripts/dglab-majsoul.user.js)
- [v1.0.0 Release](https://github.com/iSanae233/DGLab-Majsoul/releases/tag/v1.0.0)

## 使用方法

1. 在浏览器安装 Tampermonkey，再安装本项目的用户脚本。
2. 点击首页的“开始游玩”，进入配置页。
3. 连接中继，使用 DG-LAB 4 App 扫码，选择设备和输出通道。
4. 添加需要的触发事件，设置规则、强度上限和停止快捷键。
5. 保留模拟模式，打开雀魂并等待脚本关联，再点击“应用设置并启用”。
6. 查看牌局与惩罚记录，确认规则符合预期后，再决定是否开启真实输出。

也可以先打开雀魂，点击右上角的 DGLab 图标，再点击“打开并关联控制台”。两种打开方式都支持，游玩时请保持控制台开启。

游戏内默认显示一个小图标，点击后展开连接状态、最近 20 条公开事件和 5 条操作记录。面板内也可以关联控制台或停止联动。

首次打开时，控制台为模拟模式、未启用，强度上限为 0。规则和快捷键会保存在当前浏览器；刷新后仍需重新配对、关联并手动启用。修改规则、上限或通道后，已启用的联动会暂停，需要重新应用设置。

从旧版升级时，请更新用户脚本并刷新雀魂。只刷新控制台不会替换已运行的旧脚本。

## 支持范围

- 客户端：雀魂网页版，通过 Tampermonkey 获取事件。
- 网页域名：繁中服、日服和国际服。匹配这些域名不代表全部地区都完成了实测。
- App：DG-LAB 4 App，使用 V4 Socket 协议。
- 设备：App 上报的 `COYOTE_030`，即郊狼 3.0 主机。App 版本和主机型号请分开确认。

## 电击惩罚

### 触发事件

选择触发事件，点击“添加事件”创建规则。同一事件只需添加一次，可以随时编辑、暂停或删除。

支持自己点炮、打出 Dora / 赤宝牌、自己的牌被吃、被碰、被明杠，以及其他玩家立直、自摸，自己和牌、立直，流局时已听牌或未听牌。

被吃、被碰、被明杠可以分别设置。这里的明杠指其他玩家用自己的弃牌完成大明杠，不包含暗杠或加杠。

### 强度操作

| 操作 | 生效方式 | 惩罚时长 |
| --- | --- | --- |
| 临时变化 | 按设置持续，到期后撤销临时变化 | 0.1–60 秒 |
| 持久变化 | 一直保留，直至其他规则或停止操作改变它 | 不设置 |
| 临时归零 | 先归零，到期后在连接和反馈满足条件时恢复原强度 | 0.1–60 秒 |
| 持久归零 | 归零后不自动恢复 | 不设置 |

变化类规则提供两种强度动作：

- **变化**：输入 -200 至 +200 的整数，正数增加，负数减少。正数会显示 `+` 提示。
- **调整到**：输入 0–200 的目标强度，也可以使用数字步进、滑块，或在输入框聚焦后滚动调整。

实际输出同时受设置的强度上限、App 通道上限和 200 限制。缺少当前强度或上限反馈时，不执行输出。临时归零后的恢复也会重新检查反馈；停止、断开或新的任务会取消恢复。

A/B 通道可以使用相同规则，也可以分别设置。已创建规则按以下格式展示：

```text
A/B 通道  临时变化  +10  5 秒
A 通道    持久变化  调整到 30
B 通道    临时归零  5 秒
```

两通道配置相同则合并展示，不同则分为两行。归零操作不显示变化数值和强度控件，持久操作不显示时长。

### 按点炮失分缩放

“自己点炮”规则可以勾选“按实际点炮失分缩放强度变化”。计算时先对失分进行四舍五入，再乘以设置的系数：

```text
千点单位 = round(实际失分 / 1000)
强度变化 = 千点单位 × 变化系数
```

例如，3900 点按 4 个单位计算，1300 点按 1 个单位计算。系数为 +3 时，分别变化 +12 和 +3。

“调整到”模式按同样方式缩放目标强度。取消勾选后使用固定数值；归零操作不按失分增加强度。换算后的结果仍受各项上限限制。

### 勾选波形

默认不勾选，跟随 App 波形。

可以勾选多个波形，也可以全选或全不选。播放方式支持：

- **按勾选顺序轮播**：按选择顺序播放完整波形周期。
- **随机播放**：随机选择已勾选的波形，不按展示顺序播放。

临时规则在惩罚时长内播放。持久规则会持续轮播，直到下一条规则、停止或断开；每次下发的波形任务为有限时长，取消后不再续发。

### 停止快捷键

点击快捷停止键输入框，同时按下组合，松开全部按键后确认。录入时会暂停当前联动，完成后需要重新启用。

支持 `Ctrl + Alt + K`，也支持 `G + H` 等组合，最多可以使用 4 个普通键，并叠加修饰键。快捷键只在控制台或已关联的游戏窗口内生效。普通字母在输入框内打字时不会触发停止，已知浏览器保留键不能录入。

## 点炮与停止逻辑

点炮大小以服务器实际扣除的分数为准，包含本场和多家荣和造成的合计失分，不重复计算此前已扣除的立直棒。

只有完整观察到实时牌局、确认最近出牌或杠来自自己，并且结算中只有自己失分时，才会触发点炮规则。自摸、身份不明、归因不明或多人分摊支付等情况会跳过。恢复的历史动作不触发惩罚，下一局重新观察后再判定。

重复事件不重复执行。真实输出忙碌时跳过新触发，不排队；任务失败后暂停，不自动重试。停止会取消后续波形和恢复任务，并向目标通道发送清理与归零请求。

网络断开或浏览器被强制关闭时，停止请求可能无法送达。请保留 App 或设备端的停止方式。同一通道的其他 App 任务也可能影响输出，停止清理会影响该通道中的任务。

## 本地运行与部署

开发和构建需要 Node.js 22+。玩家直接使用已部署的站点和脚本即可。

```sh
npm ci
npm test
npm run dev
```

本地界面地址为 `http://127.0.0.1:4173`。本地构建的脚本只信任这个来源，`localhost:4173` 不等价。正式构建需要填写实际控制台域名：

```sh
DASHBOARD_ORIGIN=https://你的正式域名 npm run build
```

构建后，`dist/site/` 用于部署 Pages，用户脚本位于 `dist/site/userscripts/dglab-majsoul.user.js`，独立副本位于 `dist/dglab-majsoul.user.js`。

部署时先部署独立中继 Worker，再部署 Pages。配置步骤、域名变量和本地检查命令见 [部署说明](docs/DEPLOYMENT.md)。

## 实现与数据

Tampermonkey 脚本负责监听并解析牌局事件。控制台负责连接 App、设置规则和发送设备指令，中继负责 V4 配对与消息转发。

默认中继为 `wss://dglab-majsoul.pages.dev`。同一域名的 HTTPS 首页展示游戏介绍，`/play/` 提供配置页面，WebSocket 请求由 Pages Function 转发给独立 Worker 的 Durable Object。

脚本只信任构建时指定的精确控制台来源。跨页消息会检查来源、窗口、会话、脚本实例和消息序号，过期点炮事件不执行。更换域名后，需要重新构建、部署并更新脚本，详见 [通信边界](docs/DEPLOYMENT.md#通信边界)。

两端各保留最近 100 条规范化事件；控制台可复制记录，游戏面板显示其中最近 20 条。事件不包含账号 ID、认证 token、原始二进制消息或私有手牌。配对链接和设备凭据只保留在控制台内存，不传给雀魂，也不写入本地规则配置。

身份从协议中的 `authGame` 识别，不依赖旧版网页对象。观察器按连接分离请求编号和消息队列，支持 ArrayBuffer、TypedArray 和 Blob，并保留原生 WebSocket 的原型、静态常量和 MessageEvent。

协议描述继承自固定版本的 Coyote-Majsoul，不会自动更新。未知动作会被忽略，已知消息解析失败时会报告错误并暂停联动。

## 验证情况

v1.0.0 已完成三轮 Codex review，修复两项 P1 和补充复核发现的反馈过期问题，最终一轮未发现可执行的 P0/P1/P2 问题。66 项自动化测试、Pages 构建和响应头检查通过，并检查了 Chrome 桌面、390px 和 320px 布局。

Review 以静态代码检查为主。v1.0.0 新增设备输出逻辑经过模拟协议测试，未向真实设备输出。早期真实友人场的事件采集记录、当前验证范围及待验证项目，见 [验证说明](docs/VALIDATION.md)；版本改动见 [更新记录](CHANGELOG.md)。
